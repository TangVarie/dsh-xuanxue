# bazi-core —— 盲派八字解读引擎

## 运行环境

脚本相对路径以本技能目录为根，依赖 lunar_python==1.4.4。执行前设 `$env:PYTHONUTF8="1"`、`$env:PYTHONIOENCODING="utf-8"`。解释器不写死：先读 `xuanxue-orchestra` 体检写出的 `xuanxue-skills/health.json`（体检按 环境变量 → 玄学运行时 `%USERPROFILE%\.dsh\xuanxue\venv` → 本机已有 Python 解析）；都没有就跑 `xuanxue-orchestra/scripts/setup-runtime.ps1`，或设 `$env:XUANXUE_PYTHON` 指到装了 lunar_python 的 python.exe。自检：`python scripts\selftest.py`（52 项）。


本版 2026-10-11。改动记录、历史命例和评测材料在开发包里，解读时不读取。

**定位**：以盲派为主。段氏做功定推理次序；每个子问题按分层权威取主镜头（六亲以素水为主、生死以飞宫为主、应期多线平权）；夏仲奇条文是一手资料；陈秉志解析层、穷通宝鉴、滴天髓作校验。主镜头只决定默认路径，不自动判任何一派赢。

## 入口

| 入口 | 什么时候 | 做什么 |
|---|---|---|
| 全盘分析 | 给了盘，要完整看，或没说看哪方面 | 所有适用的 P0–P10，标准档报告 |
| 专题分析 | 带着具体问题来 | P0–P4 内部必做＋相关分科＋P10；涉及时间才展开 P9；先答所问 |
| 同盘追问 | 本会话已分析过同一盘 | 复用仍有效的参数和结构记录，只补跑受影响部分 |
| 历法／文献校验 | 核文献例盘、修抄写错字 | 只跑 `check_chart.py` 与来源登记，不做人生分析 |

追问复用的前提：对象、出生参数、分析口径、技能版本都没变；变了就重算受影响的部分。详见 `references/execution-protocol.md` 第二节。

**阶段状态**：已完成／部分完成／不适用／候选并行／阻塞。缺历史事实、缺 `oracle-grounding`、没指定目标年份都不阻塞；缺起运资料只阻塞精确流年定位；时辰未定时，候选间一致的判断照常做，依赖时柱的分支保留。详见 `execution-protocol.md` 第三节。

## 七条铁律

1. **排盘先行，参数可见。** 先跑 `scripts/paipan.py`；只有四柱时先跑 `scripts/check_chart.py`。参数卡上的默认值必须可见，不编造出生参数，不静默按男性、北京时间处理。时辰或节气在边界时列候选盘，只在受影响的判断上分支。
2. **按入口走，必要项不漏。** 全盘与专题都在内部做完 P0–P4；每个阶段登记状态；缺项只阻塞依赖它的部分。结束前过 `references/09` 末尾的检查清单，逐条确认或写明不适用。
3. **每条重要结论挂依据。** 靠哪个做功点（制、合、冲、穿、刑、墓）、哪条口诀或象、哪篇技法。说不出依据的不写。
4. **按分层权威取镜，先处理反证，真分叉保留。** 主镜头、计票、反证、标签、重断门槛只按 `references/authority-and-forks.md`：关键前提确定、至少两条不同来源的方法线支持、且没有未解决的反证才标【铁断】；二比一不直接升档；立极这类真分叉两读并带、标【存疑】；亡故、离丧、无子、多婚、牢狱一级的重断先过门槛。
5. **验证状态如实标。** 有已知事实先对照再预测。推导前就看过的事实只叫"已知事实拟合"，不叫盲测；没有事实写"未验证"，标签不因此机械降档；事实与结论冲突，只处理受影响的判断。规则在 `references/output-and-verification.md` 第二节。
6. **预测可检验。** 落到可观测事件、依据支持到的时间窗和判定标准；能到月给月，只能到年就写到年，不编月份。
7. **不套存盘结论，不读评测答案。** 当前盘的每个结论都从技法对当前实字重新推。修正登记里的候选规则只当检查项，不自动套到所有盘。评测题与答案、历史命例不在运行包里，解读时也不去找。

## 输出

- **档位**：简明（追问、小问题）／标准（全盘与专题默认）／详细（要完整推导、矩阵、逐年时）。档位只改篇幅，内部检查照做。先答所问，再讲结构与证据。
- **标签**：【铁断／推断／存疑】，或不作判断；判定规则在 `authority-and-forks.md` 第五节。标签说的是体系内论据强弱，不是概率。
- **验证状态**：未验证／已知事实拟合／盲测核验／前瞻检验，与标签分开列。
- **表达**：按 `output-and-verification.md` 第五节的内置表达协议：结构判断与现实翻译分开，翻译不改对象、方向、条件和标签，不凭空加行业和事件，建议对应已有判断。`oracle-grounding` 在场时可作增强层，并注明用了它。
- 全程中文。凶事给出路，吉事留余地，危及性命之断只点防范年份。

## 脚本速查

```bash
pip install -r scripts/requirements.txt        # lunar_python==1.4.4；系统 Python 加 --break-system-packages

# 给出生时间排盘（参数卡、边界候选、四柱、藏干十神、神煞查表、关系扫描、大运）
python3 scripts/paipan.py --date "1997-09-05 20:00" --gender male --lon 121.47
#   --eot 加均时差得真太阳时；--tz +8 / Asia/Shanghai；--dst yes|no；--basis mean-solar|true-solar（已校正）
#   --lunar [--leap yes|no] 农历；--ziday 23|0 换日口径；--uncertainty 15 列出 ±15 分钟的候选；--json
python3 scripts/paipan.py --date "1997-09-05" --gender female      # 只有日期：时柱暂缺，起运给区间

# 已有四柱：藏干、十神、神煞查表、关系扫描（无大运）
python3 scripts/paipan.py --pillars "丁丑 戊申 壬子 庚戌"

# 核四柱：遁法、反查时间区间、所称大运/起运/生年是否由同一个候选同时满足
python3 scripts/check_chart.py --pillars "乙未 己卯 丁丑 庚戌" --gender male --qiyun 4 --born 1955
python3 scripts/check_chart.py --repair "乙已丁庚未卯丑戌"      # 扫描错字
python3 scripts/check_chart.py --batch charts.txt               # 批量：逐行状态与分类统计

python3 scripts/selftest.py                                     # 改脚本或升级依赖后跑
```

脚本只出计算结果，不做解读。口径（节气按北京时间、日时柱按所用地方时、默认 23 点换日）写在 `scripts/chart_core.py` 开头，并打印在参数卡上。check_chart 单盘的退出码：0 通过，1 发现不一致，2 输入错误，3 运行错误；批量和修复模式跑完即返回 0，结果看输出。
