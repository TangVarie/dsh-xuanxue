# 输出与验证（展示档位、验证状态、修正登记、表达协议）

> 本篇是输出与验证的唯一规则源。标签怎么判（计票、反证、重断门槛）在 `authority-and-forks.md` 第五节，这里只管怎么展示、验证状态怎么另列、个案修正怎么登记和推广、结构判断怎么翻译成现实表达。

---

## 一、输出档位与报告结构

### 1. 三个展示档

| 档 | 什么时候 | 内容 |
|---|---|---|
| 简明 | 同盘追问、单一小问题 | 结论＋标签＋一两句依据 |
| 标准 | 全盘分析默认；专题分析默认 | 答案先行，结构摘要，关键依据，必要核验，预测点 |
| 详细 | 用户要完整推导、矩阵、逐年分析 | 加方法线矩阵、做功全表、逐运逐年、引擎权重与置信分层、执行记录摘要 |

档位只改篇幅和表格数量，`execution-protocol.md` 里的内部检查照常做。

**次序**：先回答用户问的，再讲结构和证据。传统的"先断六亲存亡镇场再答题"（`09` 第 11 步）是可选话术，不是强制流程。

### 2. 全盘报告（标准档）

```
一、命盘与参数    参数卡摘要（默认值标出）、候选盘、缺项          ← 必有
二、结构内核      势、体用宾主、做功、正反局、虚实                ← 必有
三、命主画像      性情体貌、职业、财官、六亲、婚姻、身体中适用的各项 ← 按适用
四、大运总轴      每运一句基调＋当前运干五年支五年细批            ← 需起运与性别；缺则写"部分完成"及原因
五、近年逐年      当年起连续五年，每年一句，不跳年；时间精度跟依据走 ← 需起运；缺则只给大运级判断
六、目标年精算    方法线矩阵                                      ← 仅当用户问到具体年或事
七、核验          对照已知事实并标验证状态；无事实写一句"未验证"   ← 必有（可一句）
八、建模与预测点  结构向量卡、三条贯穿线；可检验的事件＋时间窗＋判定标准 ← 有向前判断时
九、本次主要结论  有强支持的列强支持的；只有条件性结论就列条件性结论 ← 必有
```

条件段不适用就省略或写一句原因，不为凑段落编内容。"本次主要结论"不为栏目好看把【推断】写成【铁断】。

### 3. 其他入口

- **专题**：答案 → 关键依据（地基 P0–P4 的摘要，只写与问题相关的部分）→ 必要核验 → 预测点（涉及时间时）。
- **同盘追问**：直接答；注明复用了前文哪些记录、重算了什么。
- **历法／文献校验**：结果表、疑点、来源状态登记（`authority-and-forks.md` 第六节）。不做人生分析。

### 4. 展示规则

- 重要结论挂标签、关键依据和成立条件；同一组结论可以合并标注。
- 依据要说到点：哪个做功点（制、合、冲、穿、刑、墓）、哪条口诀或象、哪篇技法。说不出依据的不写。
- 标准档写"几条不同来源的方法线同指"一句即可；矩阵表放详细档或目标年精算。
- 候选盘或立极分叉时，共同结论写一次，差异部分分开写。
- 开头的答案、结论表与正文用同一个标签和同样的措辞强度；摘要不得比正文说得更满。执行记录里判为【存疑】的，回复里不只写其中一面。
- 时间精度全文一致：声明了某段只到年，后文不再拆到半年或月。用 R4 把一年拆成上下半年时，写明分界用的是公历年中还是立秋（本库未定）。

## 二、验证状态（与标签分开列）

| 状态 | 定义 | 能说明什么 |
|---|---|---|
| 未验证 | 尚无对应事实 | 保留结构推演，等待核验 |
| 已知事实拟合 | 推导前已经看过相关经历 | 解释是否一致；不能据此说"盲测命中" |
| 盲测核验 | 推导时没接触答案，输出先存档，再评分 | 对这些案例的事前判断表现 |
| 前瞻检验 | 预测先固定，目标时间过去后再对结果 | 对预先列明的事件与时间窗的表现 |

规则：
1. 已知事实要注明来源（用户本人说的、书中所记、他人转述）。不把自己以前给过的分析当作用户确认的事实。
2. 用户在一开始就给了经历，相关结论一律记"已知事实拟合"。不事后补写执行记录来伪造"先预测、后知道"的顺序。
3. 用户给了经历时，先对照这些经历（逐条标一致、偏差、未覆盖），再做向前判断。没有经历时写一句"未验证"，照常推演，标签不因此机械降档。
4. 事实与某条结论直接冲突，只修改受影响的判断，并按第三节登记；不凭一条事实给整盘加分或减分。
5. 向前的判断要可检验：写成具体可观测事件、依据支持到的时间窗、什么结果算不中。能支持到月就给月，只能支持到年或几年的窗就写到那一级。
6. 末尾留"待验证清单"，写清哪一年的什么事用来检验哪条判断。
7. 盲测与前瞻检验的结果只对那一批案例、那一个技能版本有效；技能改过之后，旧成绩不套到新版本上。

## 三、修正登记（个案修正与推广程序）

### 1. 错因选项

偏差归因可以选：势判错、主立错、时辰错、口诀误用、宾主反、**当前规则无法解释**、**规则适用范围存疑**、**事实信息不足以定位原因**。不要求每次出错都立刻写一条新规则。几种解释都说得通时，保留候选，不挑一个正好符合结果的当唯一原因。

对用户的回复里：直说哪条对不上；列出可能的原因，并说明"当前规则无法解释""信息不足以定位"这两项是否成立；事后找到的解释写成"可能是"，不写成定论；用一句话交代修正的范围、状态和否定条件（例如"只改本盘这两条判断，属候选，不新增通用规则；若某年出现某事，这次修正就不成立"）。

### 2. 有修正时记五项

原判断｜实际反馈｜调整内容｜适用范围｜什么样的后续结果会否定这条修正

### 3. 状态与用法

| 状态 | 是什么 | 怎么用 |
|---|---|---|
| 原书已有（案例提醒） | 原资料里本来就有，案例只是再次提醒 | 按原书条文使用，来源记原书；案例不额外计票 |
| 候选适用规则 | 由某个案例或某次测试新推出的假设 | 只当检查项；用到时写明"候选"；不计票，不能单独支撑【铁断】 |
| 方法纪律 | 约束分析做法，不产出命理断语 | 照做 |
| 案例背景 | 只属于那张盘的情况 | 留在案例记录里，不进运行规则 |

### 4. 候选升为通用规则的条件

适用前提写清；能列出支持的例子和反例；在**没有参与制定这条规则**的案例上检验过；误报照实报告，没有藏起来。样本不够就一直保持候选，不设"几盘通过即普适"的门槛。

用来挑规则、改规则的案例算**开发集**。开发集上的成绩只说明拟合，不说明对新盘的准确率。

## 四、凶事与措辞

- 凶事给出路（"过了某运某年就好"），吉事留余地。
- 危及性命之断只点防范年份，不说死期。
- 有几分依据说几分话；措辞跟标签走：【铁断】可直说，【推断】用"倾向、大概率"并写条件，【存疑】写两种可能和分辨办法。

## 五、内置表达协议

本节让本技能单独就能完成报告。`oracle-grounding` 在场时可以叠加它的五算子、行动卡和质检闸门作为增强层，并注明用了它；不在场时按本节写，不声称等同完整的共享技能，也不因为缺表达插件停止分析。

1. **两步分开**：先按 P0–P10 得出结构判断（用命理语言，不掺行业知识），再翻译成现实表达。内部记录保留结构判断原文，日后核验核的是它。
2. **翻译不改结论**：保留对象（谁）、方向（得或失、进或退）、条件（什么情况下成立）和标签。翻译不得新增、削弱或反转结构判断。
3. **不凭空加料**：具体行业、具体行为、具体事件，只在象法或用户给的现实信息支持时才写；否则写到类别为止。
4. **建议对得上**：每条建议说清对应哪条判断、服务用户的什么目标、在用户的现实条件下可不可行；与主判断同构，讲清机制；能给"不必做什么"的排除项时给出。
5. **化解**（清娟调候法的生活化通关：方位、颜色、认亲、择业择城）属传统建议，写明其五行依据；不替代现实中的医疗、法律、财务专业意见。
