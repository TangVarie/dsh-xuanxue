# 吠陀占星·时间校准引擎 (Vedic Birth Time Rectifier)

用已知人生事件与客观事实逆推出生时间。目标精度 ±5-10 分钟（D9 边界级别），收敛良好时可到 ±5 分钟；
收敛不足时输出候选时段 + 置信度，不强行给单点。分钟级精度只来自 D9/D10 换座点（单 D9 段宽约 9-17 分钟，
随纬度与上升星座变化，以本盘 time_scan 实测为准），不来自事件匹配，也不来自 Dasha 边界。

## 执行主线

1. 入口：用户说"不准"先按 `shared/error_correction.md` §1 分诊；时间来源可靠时先建议核对规则适配，不默认校时（见「进入条件」）。
2. Step 0：核实时间来源与误差方向，定扫描区间（不设扫描中心）。
3. Step 1-2：读 `chart_data.json`，收两腿证据（腿一事实与特质 / 腿二带日期事件），登记日期精度。
4. Step 3：先给原时刻打分；需要时 `time_scan.py` 逐分钟扫描，全候选 × 全证据填矩阵，按裁决定序定 Lagna，再逐级 D9→D10 精调；分不开出题，仍分不开声明欠定。
5. Step 4：判情况 A/B/C，写「校准达成级别」；用 `build_chart.py` 按校准后的时间与误差重排（新 chart_id / audit_id），
   结论写进 `rectification_report.md` 与 verification_record 的校时段。不手改 `structured_data.md`。
6. 校时后跑 `check_freshness.py`，告诉用户哪些旧分析失效、需要重新生成什么。
7. Step 5（情况B 必做）：在新盘上另建一轮验证；校时用过的证据标 `used_in_rectification`；验证结果不改变达成级别。

## 核心原则

- 原时间是线索，不是真值中心：先问清来源（Step 0），原值只是平权候选之一。
- 先用逻辑判断，不够再上计算工具；不做无意义扫描（5/5 + 高质量来源 + 来源误差窗口内无换座 → 直接 Step 4）。
- 校时容易过拟合：事件只是辅助证据，不是数学证明。事件越精确、越分散在不同 Dasha 期、越能区分 D9 边界，置信度越高。
- **时间精度只由来源与校时证据决定**（正本 `shared/validation_scoring.md` §3）：本模块的校时证据 = 换座点核验与 D9/D10 精调结果；
  事件匹配数、验前事命中率都不收窄误差、不升级精度。
- **5/5 ≠ 分钟精度**：5/5 匹配确认的是 Lagna 星座（约 2 小时宽）可作工作假设；是否达到高精度由时间来源、
  D9/D10 边界风险和分盘敏感度决定（Step 3a 决策表）。❌ 不得凭 5/5 声明"时间正确 / ±5 分钟"。
- **每个候选时刻用它自己的 Dasha**：出生时刻差 ±30 分钟，Moon 移约 0.27°，MD/AD 边界会漂 1.5-5 个月。
  `chart_data.json` 里的 Dasha 只属于原时刻这一个候选；其它候选一律读 time_scan 的「事件日期 × 候选时刻 Dasha」表。
- 证据不够区分时，先问能区分候选的客观事实，再请用户追加 2-3 个事件，最后才出题。
- 改时间后由 `calculator/scripts/build_chart.py` 直接重排，不让用户去别的软件反复排盘。

## 进入条件与前置数据

进入本模块（满足任一）：
- 时间来源不可靠（本人记忆、模糊记忆、未追问、未知，来源下限 ±15 分钟，`shared/data_contract.md` §4），且任务需要分盘精度；
- 边界审计显示 Lagna 或任务需要的分盘在审计范围内换座；
- 用户明确要求校准；
- 用户说"不准"，按 `shared/error_correction.md` §1 分诊为「时间问题」（多条与时间相关的结论同时偏，尤其上升或分盘敏感的部分）。

不默认进入：用户说"不准"，但时间来源可靠（出生证、医院记录等）且有效误差内 Lagna 与所需分盘都稳定 →
先建议回 core 反馈复核，核对规则在这张盘上的适配（`shared/validation_scoring.md` §3）；数据问题、规则应用问题、
解释形态问题按 `shared/error_correction.md` 各自处理。用户坚持校准时照做，Step 0 记下"来源可靠"这一先验。

前置数据：
- 有 `chart_data.json`：先跑 `python calculator/scripts/check_chart.py --dir <工作目录>`；脚本读 JSON，引用与核对读 `structured_data.md`（`shared/data_contract.md` §2）。
- 只有旧版 `structured_data.md`：出生信息齐全时直接用 `build_chart.py` 重排，否则 `import_legacy_md.py` 导入。
- 什么都没有：请用户给出生日期、时间、地点（由 calculator 排盘），或提供星盘文件走 reader 模块。

## Step 0: 出生时间来源核实与误差定向（任何扫描/提问前必做）

⚠️ 用户报的时间是「线索」不是「真值中心」。开工第一件事不是定扫描区间，而是问清这个时间怎么来的——
否则会把报值当对称误差中心、候选区间只要包住它就加权（锚定偏误）。

吠陀判据：出生时间 = 婴儿第一声啼哭的瞬间（非断脐/非登记/非抱出产房）。

### 0·前置：先分输入场景

- 【有报值】具体时间点或窄范围（"8:30""大概8点""7-8点这半小时"）→ 走 0a/0b/0c。
- 【无报值】宽区间 / 完全不知道（"7-10点""白天""上午""不确定"）→ **跳过 0a/0b**，
  把整个区间直接当扫描区间，进 Step 3a 的 Case B（纯事件宽扫描全部 Lagna 候选）。
  ❌ 禁止追问无报值用户"这个时间哪来的"；❌ 禁止套"向早平移"（没有报值可平移）。
  ⚠️ 但**夏令时确认不跳过**（见 0b，有/无报值都必做）。

### 0a. 追问来源（先问，停下等回答，再定区间）

```
在校准前先确认：您说的 [HH:MM] 是哪里来的？
  a) 身份证/出生证明   b) 医院出生登记   c) 家人看钟表记的（谁看的？当场还是事后？）
  d) 凭"大概几点"回忆   e) 剖腹产手术记录
吠陀以第一声啼哭为出生时间，不同来源相对它有不同方向的系统偏差，我要先扣掉再校准。
```

### 0b. 来源 → 误差方向 → 真实区间（禁止默认对称）

| 来源 | 偏差方向 | 真实区间取法 |
|------|---------|-------------|
| 家人看表（听到哭后才看） | 报值**晚于**真值（反应+读数延迟） | [X−5, X]，单边向早 |
| 凭回忆"大概几点" | 方向不定 + 严重凑整 | [X−15, X+15]，警惕整点/半点是凑的 |
| 出生证/医院原始记录 | 先核对记录的是第一声啼哭、分娩、断脐还是事后录入；未写明时方向未知 | 原始记录作高可靠候选；语义不明时保留双侧边界，禁止自动单边向早 |
| 身份证/转抄行政记录 | 可能来自原始医院记录，也可能凑整/转抄 | 先追溯原始来源；无法追溯时视为方向不定，不用固定分钟偏移 |
| 剖腹产手术记录 | 有时间戳，较准 | [X−2, X+2] 对称 |

⚠️ 夏令时核实（出生日期落当地夏令时期间必做，如中国大陆 1986-1991；有/无报值都做）：
  问一句："这个时间是当时钟表显示的时间（夏令时钟），还是未拨快的标准时？"
  默认 = 墙上钟：time_scan 与 build_chart 都传 IANA 时区（Asia/Shanghai），自动按夏令时换算 UTC；
  用户声明标准时 → 先用 `build_chart.py --clock-type 标准时` 重排（保留 IANA 时区，脚本换成当地钟表时间，
  见 `shared/data_contract.md` §4），time_scan 用重排后 `input.time_used`（钟表时间）+ IANA 时区扫描，
  全程同一种钟表口径，候选时刻与写回时间才对得上。
  ❌ 不确认就扫描 = 可能整盘偏一小时，Lagna 差一座，全部候选皆错。

⚠️ 多来源冲突：先分别核对每条记录的时刻语义与转抄关系。只有已知记录动作发生在啼哭之后时，
才把"向早"当弱方向先验；语义不明或有凑整/转抄可能时保留双侧候选，
禁止用固定几分钟的通用偏移直接排除候选。

### 0c. 输出来源核实结论（进 Step 1 前定稿）

```
报告时间 [X]，来源 = [a-e]（build_chart --source = […]），记录时刻语义 = [第一声啼哭/分娩/断脐/事后录入/未知]，
偏差方向 = [向早弱先验/双侧/待核]，夏令时 = [不涉及/墙上钟/标准时]
→ 初始扫描区间 = [起]~[止]（语义未知时不用固定分钟偏移排除任一侧）
```

来源写进 `chart_data.json` 时用 `shared/data_contract.md` §4 的来源表（它决定有效误差的来源下限）：
出生证明 → `出生证`；医院原始记录、剖腹产手术记录 → `医院记录`；家人当场看表 → `家人明确记忆`；家人事后回忆 → `家人记忆`；
凭"大概几点"回忆 → `本人记忆` 或 `模糊记忆`；身份证等转抄、追溯不到原始记录 → `未知`。
核实后的来源与 `chart_data.json` 现有 `input.time_source` 不同 → 先用 `build_chart.py` 按原报时、新来源重排，再进 Step 1。

❌ 禁止：未问来源就拿报值定对称区间；候选区间"包住报值"就加分；把整点/半点报值当精确值。

⚠️ 向早平移只是弱先验：
- 只用于把【有报值】的初始扫描范围从对称窗削成单边，缩小枚举范围；任何一条事件裁决都能覆盖它。
- 进入 Step 3 后**不再参与裁决**——Lagna 与分钟由两腿证据 + D9/D10 定；❌ 禁对已被证据验证的时间硬往早推。
- 校准完成后（Step 4「来源偏差回顾」）只作结果解释。

## Step 1: 数据准备

从 `chart_data.json` 读取（脚本读 JSON；模型引用与核对读 `structured_data.md` 的对应表）：
```
必需数据：
  1. 出生日期、报时、计算用时间、钟表时间性质（input.date / time_reported / time_used / clock_type）
  2. Step 0 定下的来源与区间
  3. 出生地坐标 + IANA 时区（input.lat / lon / tz）
  4. 声明误差、有效误差、审计范围（input.declared_minutes / effective_minutes / audit_minutes）
  5. Lagna 度数和星座 + 分盘边界审计（chart.lagna、chart.divisional_boundary_audit：D1/D9/D10/D4/D5 在审计范围内是否换座）
  6. Vimsottari Dasha 时间线：`calculator/scripts/dasha_query.py --file chart_data.json --check`
     核对 MD=9/AD=81/PD=729 且三层 [start,end) 连续；`--overview` 读非 PD 内容，不默认展开 729 行 PD。
     ⚠️ 这条时间线只属于**原时刻**这一个候选；其它候选的 Dasha 读 time_scan 事件表。
  7. 宫主表（chart.house_lords）
  8. 行星落宫表 + 「Graha Drishti」表
  9. Chara Karakas（主表用 7K，`shared/data_contract.md` §6）
```

确定扫描范围（枚举候选，不设"扫描中心"）：
```
范围宽度 = 报值精度 + 来源方向（可单边，不强制对称）：
  【有报值】精度±分钟级→宽~15分钟 / ±15分钟→~30分钟 / ±1小时→~60分钟；
    来源单边偏差 → 范围单边（如[报值-N, 报值]）。time_scan 的 --range 是对称的：
    单边时取较大一侧的宽度，窗口外的行不进候选。
  【无报值】用户给宽区间/完全不知道 → 范围 = 用户给定区间（或全天）；
    --time 取区间中点、--range 取半宽。

⚠️ 在范围内**枚举所有 Lagna 候选**（每一段连续上升弧 = 一个候选），全部进 Step 3 评分。
   ❌ 禁用"中心±"框把真值 Lagna 框在范围外（锚定偏误）。
```

## Step 2: 证据采集

两类证据都收、都进评分（见 3c 主纲「两腿等权」）：
- **腿一 = 事实与特质**（不带日期）：兄弟姐妹、父母、婚育、怀孕方式、相识方式、配偶职业、本人职业与权责、专业、病种、出国……
- **腿二 = 带日期事件**：婚/丧/职/灾/财/学业/迁徙/健康

### Step 2a: 先取已有信息

```
执行顺序：
  1. 读 chart_data.json / structured_data.md + user_context.md（若存在）
  2. user_context.md 读取范围（权限正本 `shared/permissions.md` §4：rectifier 全程可读、负责建档维护；
     本模块自我限制为只读校准用得上的事实项）：
     - 腿二：已有的"事件主题 + 日期（及日期精度）"
     - 腿一：客观事实项——亲属结构、父母存殁、婚育、怀孕方式、相识方式、配偶职业、
       本人职业与权责、专业、确诊病种、出国/长住外地
     - 不读：核心关切/咨询问题、验前事逐条反馈、感情经历细节、性格自述等叙事内容
       （不是校准证据，读了只会诱导拟合）
     - 评价类特质（家庭氛围、关系好坏、性格）只在出题时用于 calibration_quiz 的
       「已知检」「领域适用」，❌ 不用来决定"候选→答案"映射
  3. 输出已知清单给用户确认，只问缺失项：
     "我从之前的对话中提取了以下信息用于校准：
      事件：1. [事件主题] - [日期]  2. ...
      事实：[兄弟姐妹/父母/婚育/职业…]
      还需要补充：[列举缺失的类别]"
  4. 已有带日期事件 ≥ 5 个且腿一事实已覆盖 → 直接进入 Step 3；否则进入 Step 2b
```

### Step 2b: 补充收集（只问缺失项，❌ 禁无视已有内容整张模板重问）

```
要做出生时间校准，麻烦你提供两类信息——都能帮我定位时间，越多越准：

【一、事实与特质】（不用日期；能具体说出来的都算，没有或不清楚的跳过）
  · 兄弟姐妹几个、你排第几（有没有哥哥姐姐 / 弟弟妹妹）
  · 父母是否健在；若有一方在你成年前离世，当时你大约几岁
  · 婚姻状况（未婚 / 已婚 / 离异）、有没有孩子；怀孕是计划内还是意外
  · 和配偶怎么认识的（相亲 / 同学 / 同事 / 网上…）、配偶做什么工作
  · 你的职业、职位与权责（是否带团队、管多少人、在单位里大概什么层级）
  · 大学 / 所学专业
  · 确诊过的严重疾病或慢性病（说病名）
  · 有没有出国或在外地长住
  · 其他你觉得"和别人不一样"的具体情况

【二、带日期的重大事件】（记得哪年、最好到月，如"2020年6月 父亲去世"）
  ⚠️ 要"有区分度"的——上小学/上初中这种大家时间都差不多的别提；
     要你人生里"和别人不一样"的转折：
       · 升学里非常规的（跳级 / 复读 / 转学 / 留学 / 辍学）
       · 搬家 / 移居 / 出国
       · 重病 / 手术 / 住院
       · 感情大事（在一起 / 结婚 / 分手 / 离婚）
       · 事业大事（入职 / 离职 / 创业 / 升职 / 被裁）
       · 家庭变故（亲人离世、父母重大变动）
       · 财务大起大落（大笔进账 / 大额亏损）
  下限 5 个，越多越准；婚/丧/职/灾/财 各一个最理想
```

⚠️ 不采用：身体特征（头发/胎记/外貌/出生体重）、伤疤位置、疾病外观——
   本系统明确弃用此类证据（详见 resources/event_house_map.md）。
⚠️ 关系好坏、家庭氛围、性格这类"怎么都像"的描述可以记下，但不直接计分，留作出题素材（resources/calibration_quiz.md）。

### Step 2c: 分类与登记

### 3b. 时间扫描

**环境**（time_scan.py 与 calculator 模块共用环境，❌ 别用裸系统 python）：
```
1. 用 calculator 模块的环境：<工作目录>/vedic-calc-env/bin/python（skill 目录只读时 setup_env.py --target 建在这里），
   或 <vedic skill>/calculator/venv/bin/python（Windows: ...\Scripts\python.exe）；check_env.py 会报告可用路径
2. 没有 venv → 先跑 calculator/scripts/check_env.py 自检，或 setup_env.py 建好
3. 当前 python 已能 import swisseph（swe.version≠'0.0.0'）且能 import PyJHora → 直接用
不需要 ephem；不要裸 pip install pyswisseph / PyJHora（缺依赖和星历）。
```

运行脚本（--date/--time 一律是 **--tz 下的当地钟表时间**；脚本自己换算 UTC，跨零点自动退日）：
```bash
<calculator venv python> scripts/time_scan.py \
  --date [本地出生日期 YYYY-MM-DD] \
  --time [本地预估时间 HH:MM] \
  --tz [IANA 时区，中国大陆 Asia/Shanghai] \
  --lat [纬度] --lon [经度] \
  --range [扫描范围] \
  --event-date [事件日期，可重复：YYYY / YYYY-MM / YYYY-MM-DD，可加 =标签] \
  --save rectification_scan.md
```
- **--tz 必传**。IANA 名自动处理夏令时和历史时区（含中国 1986-1991）；数字偏移（`8`、`5.5`）是固定偏移、不处理夏令时；
  已是 UTC 传 `UTC`。用户声明"标准时"时按 Step 0：用重排后的钟表时间 + IANA 时区扫描，与写回保持同一口径。
  `--local-date/--local-time` 是同义别名。
  ⚠️ --date/--time **不是 UTC**，❌ 不要手算 UTC 再传。
- **--event-date**：把腿二全部事件都传进去。第一轮不加 `--pd`（只算 MD/AD）。
- **--pd**：全候选 MD/AD 矩阵填完、仍有可靠到月/日的事件需要 PD 分辨时再加（见 3a PD 审计）。
  只记得年的事件自动不给 PD。
- `--endpoint-start/--endpoint-end`：只决定文末"两点法"完整时间线取哪两个偏移（默认扫描两端）。
- 耗时：每个 Dasha 探测点约 1-2 秒；±30 分钟、3 个事件约 30-50 秒。

**读扫描结果**（读 rectification_scan.md）：
1. **先核表头**「基准: 本地 … = UTC …」里的本地日期时间与用户报的一致（跨零点、夏令时在这里暴露）；展示给用户时优先用本地时间。
2. **逐分钟表**：Lagna 度数、D9、D10、Moon 宿；本地日期与基准日不同的行带月-日。
3. **关键变化点**：★ Lagna 换座（宫主表完全改变）/ ◆ D9 换座（约每 9-17 分钟，随纬度与星座变）/ ◇ D10 换座 /
   ⚠️ Moon 跨 Nakshatra（出生时所在大运主星改变；出生后各事件的归属仍随出生分钟连续推进，
   事件表已按分钟给出，无需手工切段）。

### 3c. 逆推最佳时间

⚠️ 铁律（反故事拟合）：禁止先看一眼盘选定一个故事（如"8年产出=稳定积累=Taurus"）再回头拟合所有事件。
必须把**全部候选并列**，用**同一套全部证据**对每个候选**逐条独立打分**，先填满评分矩阵、最高分胜出，
**才允许写叙事标签**。

> **过拟合防线·主纲——两条腿等权计分；护栏管的是"每条证据怎么计"，不是"哪条腿不算"：**
> - **腿一 = 事实与特质（不带日期）× 候选间确有变化的静态盘面字段**：用户能具体说出、不是模棱两可性格描述的都收——
>   亲属结构、父母、婚育、怀孕方式（计划内/意外）、与配偶相识方式、配偶职业、本人职业与权责、专业、病种、出国等。
>   取宫：resources/event_house_map.md「静态事实映射」是常用示例；表外事实按同文件「核心映射」取宫/宫主/Karaka，对照前现场预登记。
> - **腿二 = 带日期事件 × Dasha**：每个候选时刻的 MD/AD 读 time_scan 事件表，按 3a 四层法打分。
> - **两腿等权**：腿一一条 ✅ 与腿二一条 ✅ 同值，合计进总分、定 Lagna 门槛、裁决定序；❌ 禁预设哪条腿天然压另一条。
> - **计分资格看区分度**：
>   · **预登记**：对照用户事实前，先在聊天框列"候选间变化的字段 → 取宫规则 → 每个候选的预期（支持/否定/中性）"；
>     能写出"某候选下该条不成立"的才计分。对照中 ❌ 禁增删、换规则；同一规则施于全部候选；对照后才想到的规则不计分。
>   · **只计变化字段**：该条涉及的宫、宫主、自然征象星、分盘在候选间都不变 → 对区分零贡献，不计分。
>   · **不直接计分**：泛画像、自我感、关系好坏、氛围、性格（如"和父亲很疏远"）——说得再肯定也一样；
>     留作出题素材，矩阵分不出时按 resources/calibration_quiz.md 出题，作答前锁定映射，有效题才计分。
>   · **同源去重**：指向同一组盘面字段的多条只计一次（如"父亲早逝"与"由母亲独自带大"都落 9宫/9主/Sun）；同一现实过程的多条事件同理。
>   · **淘汰三门槛**（缺一只扣分、不淘汰）：a) 事实客观可核且经用户确认；b) event_house_map 该行标"可淘汰"；
>     c) 该行全部指征在该候选下同向否定。自然征象星不随候选变化——它若支持该事实，c) 不成立。
>   · **Dasha 不得复活**：被腿一淘汰的候选不得用腿二复活；全部候选都被淘汰 → 不选，回查事实与规则。
> - 贯穿 D1 / D9 / D10 各层：
>   · **① 绝对独立打分**：每候选先各自判"匹配/不匹配"再比；❌ 禁因"另一候选更亮"就把一个独立看全面匹配的候选评为弱。
>   · **② 结果与来源方向相悖 = 硬红旗**：定盘后若结果偏移方向与 Step 0 来源系统偏差方向相反 → 降置信 +
>     回查决胜证据是否都预登记、都过区分度，❌ 禁生成"可能凑整/入产房"之类事后合理化。
>     但逆向不是禁止：有预登记、计分合格的证据给出明确分差时，逆向成立，需显式说明是哪几条证据压过来源先验。

   - 该级主要靠腿一 × 分盘变化字段（D9 对婚育、相识方式、配偶职业；D10 对职业、职位权责、专业），
     同样预登记、只计变化字段、同源去重；合计仍 <2 → 出题。

### 反证强制重检（贯穿 3a–3c，每条新信息进来必跑，禁止打发）

⚠️ 每当用户补充新信息（新事件/新事实/新来源/纠正旧说法），不许只问"它符不符合当前结论"，
必须问"它会不会**推翻**当前结论"。校准最大的失败模式是：选定领先候选后，对反证一律用
"单一事件不足以推翻全面领先"打发，死不回头。

**新信息三问**（每条写进聊天框）：
  问1 归属：指向哪个候选？支持当前盘还是某个被淘汰候选？
  问2 计分资格：腿一（预登记时写得出"某候选下不成立"、且对应字段在候选间变化）/ 腿二（带日期事件×该候选各时刻的 Dasha；
      带"意外/突变/反常"方向词的按硬证据规则正面计）/ 不直接计分（泛画像、自我感、关系好坏、氛围 → 记作出题素材）？
  问3 翻转：若成立要换盘吗？加进 3c 评分矩阵，重算总分，看排序变没变。

❌ 禁止用"单一事件不足以推翻全面领先"打发硬反证。「不足以推翻」只有在**已纳入重算、且重算后排序确实没变**时才能说，
且必须附重算后具体分差；未重算就说 = 违规。

⚠️ 复检范围（防"锁死后层内自洽"）：新信息触发的重算**不只在当前锁定段内**，必须回 3c 全候选矩阵——
**含被淘汰的其他 Lagna 候选段**（新增日期事件就把它加进 time_scan --event-date 重跑一次，补算该事件在全部候选段的归属）。
任一被淘汰候选重算后追到当前锁定段 **3 分以内**（<2 翻转阈值 + 1 缓冲）→ 从 3c 全矩阵重开 D1 层复检。

**输出**（每轮新信息后写聊天框）：
```
反证检查：新信息[X] → 指向候选[A/B]，[腿一/腿二/不计分·出题素材]
  → [已纳入3c重算 / 暂存待出题] → 重算后 候选A[分] vs B[分]
  → [翻转改判A / 未变，B领先N分，理由…]
```
⚠️ 凡写"未变"必须给出重算后具体分差，禁止只写"不足以推翻"。

⚠️ 来源更正联动（任何阶段，含校准完成后）：用户提供"出生时间来源"新信息（如事后才说"是医院时间""家人当场看表"）：
   → 视为**强先验**，回 Step 0 按新来源重定误差方向/区间，触发全流程重估
   → 但来源不是 ground truth：医院时间也可能偏（补记/凑整/看表滞后），不硬覆盖证据结论
   → 证据稳定地与来源冲突时 → **标注冲突**，呈现两种可能 + 各自证据，而非无条件改判到来源窗口
   → 来源变了会改变有效误差的来源下限：重估后按 Step 4「写回」用新 `--source` 重排（时间不变则 chart_id 不变、audit_id 可能变）

## Step 4: 输出结论

**⚠️ 首先判定情况（先看有没有欠定 → C；没有再按偏移分 A/B）：**
```
情况C（收敛不足）= 某一层出现欠定声明（两腿合计差 <2、出题后仍 <2、无新角度）：
  C-1  D1 层欠定：候选时段落在不同 Lagna
  C-2  D9 及以下层欠定：Lagna 已定，D9（或 D10）候选分不开
  （没做精调、用户止于粗级 ≠ 欠定，按 A/B 判，达成级别记 Lagna 星座级）

情况A（不改时间）= 无欠定，且全部满足：
  1. 推荐时间与原始时间偏移 ≤ 5分钟
  2. Lagna 星座与 D9 Lagna 都未变化

情况B（改时间，收敛良好）= 无欠定，且任一成立：
  1. 推荐时间与原始时间偏移 > 5分钟（D9 精调后的推荐时间也算：原 01:30 → 精调后 01:45 = 情况B）
  2. D9 Lagna 发生变化
  3. Lagna 星座发生变化
```

### 校准达成级别声明（三种情况都必写）

```
【校准达成级别】<D9+D10 级 / D9 级 / Lagna 星座级 / Lagna 星座级（D9 欠定） / 欠定>
  可行窗口：±N 分钟（最终可行窗口半宽，按本盘 time_scan 实测换座点算；情况C = 全部存活候选段的并集相对写回时刻的最大偏移）
  有效误差：±M 分钟（写回后 chart_data.json 的 input.effective_minutes，见下方「写回」）
  依据：<精调执行到哪一级 / 来源窗口+边界核验 / 欠定在哪一层、为何分不开>
  时间可信度：<高/中/低>
  未定项：<无 / "时间仍未定（D9 层）" / "时间仍未定（Lagna 层）">
```

| 结果 | 达成级别 | 时间可信度 | 未定项标注 |
|------|---------|-----------|-----------|
| 最终窗口落在单一 D9 段（含 D10 交叠段）且无欠定——由 D9 精调定出，或由出生证/医院记录 + 窗口内无换座核验 | D9 级 / D9+D10 级 | 高 | 无 |
| Lagna 已定，窗口仍跨 D9 换座点（5/5 未做精调 / 用户止于粗级 / 来源窗口跨 D9） | Lagna 星座级 | 中（报告 D10/D5/D4 引用留余地）；例外：校准前因可靠来源（出生证、医院记录）为"高"、本次未推翻原 Lagna 且无反证 → 保持"高"。校准前的"高"若来自验前事命中、来源本身不可靠，不适用此例外（`shared/validation_scoring.md` §3）。分盘一律按有效精度行 | 无 |
| 情况C-2：Lagna 已定、D9 层欠定 | Lagna 星座级（D9 欠定） | 中，分盘可信度=低 | "时间仍未定（D9 层）" |
| 情况C-1：D1 层欠定 | 欠定 | 低 | "时间仍未定（Lagna 层）" |

⚠️ 达成级别只看最终可行窗口跨不跨换座点：来源可以把窗口收窄到它可信的程度；5/5 和验前事命中都不提升级别。
reader、core 读校时段里的达成级别与时间可信度，分盘启用按 `chart_data.json` 的有效精度取行（`shared/divisional.md` §1），不按"经过 rectifier"一刀切。

### 写回（三种情况都按此做；不手改 structured_data.md）

工作目录的 `verification_record.json` 留给新盘（`shared/validation_scoring.md` §4）。正本：`shared/versioning.md` §3。

**2. 用 build_chart.py 重排**：
```bash

  --date <出生日期> --time <写回时刻> --tz <IANA 时区> --lat <纬度> --lon <经度> --place <地点> \
```

- 写回时刻：情况A = 原时刻；情况B = 校准时间；情况C = 最佳估计段内的工作假设时刻（报告写明取法）。
  钟表口径与 time_scan 一致（钟表时间，`--clock-type` 用默认值）；用户原报若是标准时，在 `--declared-text` 注明。

  有效精度档按 `shared/data_contract.md` §4 的标签由脚本写出；rectifier 不手写这些字段。
- 可行窗口窄于原来源下限（例：本人记忆 ±15，D9∩D10 定到 ±4）是校时的意义所在：chart_data.json 记 ±4，分盘启用按重排后的边界审计取行。
  校时容易过拟合，所以同时写清达成级别与时间可信度（校时段），reader、core 引用分盘结论时一并说明"时间经校时，可信度 …"。

```
## 区分条件
要进一步确定，请补充任一未参与校准的信息：
  - 能区分候选的客观事实（按候选间差异字段挑：兄弟姐妹、父母、婚育、配偶职业、职位权责…）
  - 童年结构性事件年份（搬迁、家庭变动、转学）
  - 升学 / 重大疾病住院 / 长期外宿的年份
  - 亲属重大事件（父母离异 / 兄弟出生 / 祖辈过世）的年份
  - 出生手环 / 医院原始记录等外部锚（有就用，没有不卡）

⚠️ 不要采用：身体特征（头发/胎记/外貌/出生体重）、伤疤位置、疾病外观（详见 event_house_map.md）。
```

## Step 5: 盘外验证（Out-of-Sample Validation）

**Step 5 触发条件：**
```
  情况A（不调整时间）
    → 不必执行：没有产生新假设。时间可信度按来源与达成级别（`shared/validation_scoring.md` §3），不看验前事命中率；
      现有验证记录仍绑定当前 chart_id，继续有效（与校时证据同源的题已在「写回」补标）。
  情况B（调整时间）
    → 必须执行：新时间是新假设，在新盘上另建一轮验证。
  情况C（候选时段）
    → 对每个仍存活的候选段各出一组陈述（同一领域、同一颗粒度），作答前锁定"陈述→候选"映射
      （同 calibration_quiz.md 的锁定规则）；命中按腿一计分，回 3c 裁决定序重判。
      这些陈述用于裁决，属于校时证据：记进 rectification_quiz.md 与校时段 evidence_used，不当作独立验证。
      ❌ 不另设"哪段命中率高就选哪段"的捷径；重判后仍 <2 → 维持候选段方案，标注精度限制。
```

**校时证据与验证分开**（登记、标志与评分的正本 `shared/validation_scoring.md` §1、§2、§4）：
```
校准用过的事件、事实、出题作答 = 训练数据：列在校时段 evidence_used
盘外预测 = 测试数据：用户从未提到的新推断
两组显式标注，禁止混用（避免循环论证）
- 新一轮写进新盘的 verification_record.json（chart_id = 写回后的 chart_id，round 编号按 reader 的规则）；旧盘记录在 archive/<旧 chart_id>/，不迁移
- 探针陈述的就是 evidence_used 里的事件/事实、或由它直接推出 → flags.used_in_rectification = true，不计入独立验证
- reader 的校准后重验和以后各轮验证同样按 evidence_used 打这个标志
```

### 模式A：陈述式盘外预测

**必须套用 reader 模块 Step 5（验前事）的完整构造规范**（候选池、四通道、P1/P1.3/P5 工具箱、
反恒真检查、替补机制、输出模板），不是随口出两句就算。复用时 reader 的流程指针按本模块语境读：
"Step 5"= 本模块盘外验证；"→ 进 core"= 本模块 Step 4 结论之后的去向；"→ 转 rectifier"= 已在此，忽略；
真正共用的是方法学（多推法一致性 / 安全约束），不是流程走向；时间可信度不由这轮验证决定。

rectifier 特有约束：
```
1. 目标 5 条陈述式预测；信号不足时按 SOP 替补机制处理，穷尽仍不足可诚实减至 3 条——绝不凑恒真。
   ❌ 禁止提问或诱导式（"你是不是…？"会污染验证）。
2. 预测类型配比：至少 2 条结构性事实（父母/学历/搬迁/经济）+ 至少 2 条时间锚定事件（Dasha 时期→事件类型），
   其余为家庭结构/职业领域等客观事实（参考 event_house_map.md「客观可验证事实清单」）。
3. ❌ 禁止基于已用于校准的事件/事实反推（循环论证）；盘外预测针对【未覆盖领域】——
   校准用了事业 → 盘外就出感情/家庭方向。
4. ❌ 永久禁止：身体标记、伤疤位置、疾病预测、外貌描述、性格描述（与 reader 验前事【永久禁止】列表统一）。
5. 对照组自检：每条预测先问"校准前的旧盘会不会给出同一条"——会 → 该条对新旧盘无区分，不用作盘外验证题，按替补机制换一条。
6. 构造过程完整展示在聊天框（强信号筛选 → 宫位效率 → 陈述措辞），❌ 不许只甩结论。
```

输出模板：
```
📋 盘外验证 — 校准后新预测

以下预测基于校准后的星盘推导，均为您未曾提及的内容：
（🧪 = 测试数据，与校准证据完全无关）

🧪 1. [结构性事实：父母/学历/搬迁等]
🧪 2. [结构性事实]
🧪 3. [时间锚定：某大运期间 → 具体事件类型]
🧪 4. [时间锚定：某小运期间 → 具体事件类型]
🧪 5. [家庭/职业/教育领域预测]

请逐条回复：准 / 不准 / 部分准（记不清可以直接说）
```

### 模式B：时间线交叉验证（用户愿意提供更多信息时）

```
1. 从校准用的证据中找出未覆盖的领域（至少2个）
2. 向用户收集该领域的客观时间线
3. 用校准后的盘做 Dasha 匹配（同 Step 3a 四层标准）

⚠️ 模式B计分口径（防基础率虚高）：
  模式B 比的是"事件 × 新盘 Dasha"的匹配强度，不是用户对探针的反馈，所以不套用 validation_scoring §1 的"部分准 = 0.5"：
  部分准是用户确认了陈述的一部分；⚠️ 弱匹配是盘面只泛泛对上，不构成独立命中。
  ① 只有 ✅✅ 和 ✅ 计入匹配率分子，⚠️ 弱匹配不计
  ② "角色匹配"属泛信号，不得单独计为一条命中——必须与四层中至少一层同时成立才计 ✅
  ③ 对照组自检：抽 1-2 条事件在校准前的旧盘上按同一标准打分，
     若旧盘匹配率与新盘相当 → 输出"验证不具区分度"而非"✅ 通过"
```

### 评分

```
模式A：按 shared/validation_scoring.md §1-§2 登记与定级——
  python shared/scripts/score_probes.py verification_record.json --chart chart_data.json
  输出必须同时显示总题数、不计入的题及原因、有效题数、已答、待核（记不清）、未答、匹配率、等级。
模式B：按上方计分口径算匹配率，分档阈值同 §2。

  高（≥80%）     → 盘外验证未发现反证
  中（60%-80%）  → 逐条看不准的项是否为真实偏差
  低（<60%）     → 盘外验证未达标，在报告标注；可建议用户追加事件
  暂不定级       → 有效已答少于 3 题、仍有未答，或待核超过有效题的 1/3：补题或等反馈
  无效           → 记录有非法反馈或绑定的不是当前盘：修正后重评

⚠️ 不论哪档都不改变达成级别和有效误差：验证命中不收窄误差，验证落空也不自动判定时间错（shared/validation_scoring.md §3）。
⚠️ 不准的项经用户确认是真实偏差 = 硬反证 → 回 3c 全候选矩阵按「反证强制重检」重算，不得只标注了事；
   重算用到的这些项从此是校时证据：加进 evidence_used，在验证记录里补标 used_in_rectification。
   排序变了 → 按新结果重新走 Step 4 写回。
```
