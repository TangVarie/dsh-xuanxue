# 能力表与降级路径（正本）

入口和各模块共用。先判断手上有什么材料，再决定能做什么、要限制什么。`check_chart.py` 打印的「能力范围」（structured_data.md 校验结果下也有同一张表）是这张表在具体一张盘上的结果：分盘按 `shared/divisional.md` §1（有效精度 × 边界审计，含 D1 上升），Dasha 窗口按 `shared/time_window.md` §1（层级检查 × 出生时间误差带来的日期平移）。

## 1. 按材料决定能力

| 当前材料 | 可以执行 | 需要限制的部分 | 入口 |
|---|---|---|---|
| 完整出生信息（日期、时间、地点） | 排盘及全部后续分析 | 按有效精度与边界审计限制分盘（`shared/divisional.md`） | `calculator/scripts/build_chart.py` |
| 计算环境不可用，但导出的盘数据充分（PDF、截图、文本、旧 md） | 导入、校验、基于已有数据的分析 | 缺失的计算与未验证的部分（不补成已验证） | reader 提取 → `import_legacy_md.py`；能装环境时改走排盘 |
| 只有 MD/AD，没有 PD | 结构分析、阶段窗口 | PD 支持的月级判断 | `dasha_query.py --check` 会给出「月级窗口：未完成」 |
| 出生时间不确定 | 不依赖未知时间的部分；必要时做候选分析 | 不稳定的上升、宫位与分盘 | 按有效精度排盘（审计范围同步放宽）；rectifier |
| 合盘一方只有日期 | 当日稳定的行星星座与宿与对方盘的接触；Moon 宿稳定时的月宿筛查 | 上升、宫位叠盘、UL、DK、Dasha 时机、不稳定的宿 | `build_chart.py --date-only` → synastry |
| 缺少某个专题字段 | 该专题里可用的部分 | 缺项对应的结论 | 模块按缺项降级，写明缺什么 |
| 没有出生信息，只有一件具体的事要问 | 提问盘（prashna）：这件事成不成、某人会不会动、大致何时 | 人生趋势、性格、长期运势（这些要本命盘） | `prashna/MODULE.md`；提问时刻与提问地点由提问人给 |

## 2. 按任务定义最低输入

| 任务 | 必需 | 缺了怎么办 |
|---|---|---|
| 排盘 | 出生日期、时间、地点（经纬度与 IANA 时区） | 缺时间 → 只能做仅日期模式；缺地点 → 问一次 |
| 读盘导入 | 行星星座与宫位、上升 | 缺上升 → 只做行星层；其余缺项标「未提供」继续 |
| 完整分析（core） | 通过检查的 D1 数据 | Dasha、分盘、SAV 各自缺失只限制对应部分 |
| 事业 / 感情 / 灵魂专题 | D1；D10 / D9 与 Karaka 分别对应 | 缺 D10 → 事业只做 D1 层；缺 8K → soul 只用 7K |
| 时机 | Vimsottari（月级要 PD） | 缺 PD → 阶段窗口；缺 Dasha → 只做行运 |
| 年盘（Varshaphala） | 年盘 Lagna 与年盘行星位置（本 skill 未实现太阳回归） | 完成 Muntha 等可用部分，列出缺项，不出伪精确结果 |
| 校时 | 出生时间候选范围 + 事件 | 事件不足 → 情况C 候选时段 |
| 合盘 | 双方各一份排盘数据 | 一方只有日期 → 第 1 节的降级路径 |
| 卜卦（prashna） | 一个具体问题、提问时刻、提问地点（能确定 IANA 时区） | 问题模糊或一句多问 → 先澄清、先选一个；地点未知 → 问一次；不用出生信息，也不读本命盘 |

reader 的「关键数据」以本表为准：按用户选的任务决定必需字段，缺非必需字段时继续并标缺项，而不是全部停下。

## 3. 降级时怎么写

- 写明限制了什么、因为缺什么，不写"数据不足无法分析"一句带过。
- 降级的结论在报告里带标记，综合结论里也不能升级回去。
