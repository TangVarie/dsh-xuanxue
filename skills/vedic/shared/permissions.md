# 背景信息权限与分析模式（正本）

本文件是「背景信息权限」「盲审模式」「推导阶段」的唯一正本。

## 1. 两个不同的概念

- **按盘面推导**：每条结论都必须有盘面依据，不迎合用户经历。所有模块、所有阶段都要做到。
- **严格盲审**：初始推导的执行环境实际没有接触过用户经历或反馈。同一会话里已经看过用户经历，仅仅"不再打开背景文件"，不能算严格盲审。

## 2. 分析模式（写进 analysis_record，报告页脚照写）

| mode | 条件 |
|---|---|
| `strict_blind` 严格盲审 | 初始推导在单独的执行环境完成（例如只拿到 `chart_data.json` / `structured_data.md` 的子任务），没有接触用户经历和反馈 |
| `chart_derived` 盘面推导 | 结论都有盘面依据，但执行时同一会话接触过用户经历。没有条件做隔离时的默认值 |
| `calibrated` 反馈复核后 | 初始结论冻结后，读过验证记录或用户反馈并复核 |

不能证明隔离时一律写 `chart_derived`，不得自称盲审。

## 3. 三个阶段

| 阶段 | 可以使用的信息 | 产出 |
|---|---|---|
| 初始推导 | 计算数据、输入质量、能力范围（`check_chart.py`） | 初始结论及依据，写入 analysis_record 后 `freeze` |
| 反馈复核 | 冻结的初始结论、验证记录、用户反馈 | 每条差异：保留 / 修正 / 未解决，写变更日志 |
| 表达与建议 | 已确定的结论、用户现实处境（user_context） | 用户能读懂的报告与建议（core Step 4.5、落地层） |

- 先冻结初始结论，再读反馈。区分"见过"与"用过"：
  - 同一会话里之前见过验前事反馈或用户经历（例如 reader 验前事流程、上传的旧文件里带反馈节），但初始推导没有打开验证记录、没有据反馈下结论 → `chart_derived`（本来就不是严格盲审）。
  - 初始推导中读取或引用了验证记录 / 用户反馈 → 只能写 `calibrated`，且不能声称初始结论独立。
  - 冻结之后按反馈复核 → `stage --read-feedback`，mode 自动改为 `calibrated`。
- 验证记录（含旧流程的「信号修正日志」）不得出现在计算数据里，也不得经由 core_summary 等摘要流回初始推导。
- 表达阶段只改措辞和落点，不新增、削弱或反转结论。表达阶段可以读反馈等级，用来加一句低反馈声明；这不改结论，也不改变 mode。
- 只因用户反馈而修正的结论，修改只落在表达层文件（如 core 的 p5a/p5b）与分析记录里，不回写 p2a~p4、core_summary 这些盲审模块会读的文件，避免反馈流进它们的输入。读数错误、规则应用错误这类硬错，所有受影响文件都要改。

## 4. 各模块对 user_context.md 的权限

| 模块 | 读 | 写 |
|---|---|---|
| reader、rectifier | 全程可读 | 建档与维护 |
| core | 初始推导（Step 1-4）与 Step 5 不读；Step 4.5 只读；QA 阶段必读 | QA 阶段只追加用户新补充的传记事实 |
| career、love、soul、synastry | 不读 | 不写 |
| timing | 只在 Mode B 历史回测读「事件主题 + 年份」 | 不写 |
| prashna | 不读（也不读本命产物；本命交叉失败关闭） | 不写 |

- 盲审模块引用 core 结论时只读 p2a~p4 与 core_summary.md；p5a/p5b 经过 Step 4.5 按 user_context 改过措辞，不读其正文。
- 这些模块的 QA 需要背景时，回到 core 的 QA 阶段处理。
- 增量追加只写用户关于自己人生的客观陈述；寒暄、情绪、对结论的评价不写。

## 5. 结论修改

措辞校订阶段锁定结论。以下三种情况允许修改结论，但必须记录：

1. 读数错误（读错了表、抄错了数）
2. 规则应用错误（用错口径、漏了条件）
3. 新输入推翻旧前提（出生时间改了、补了数据、旧盘失效）

记录格式（`analysis_record.py change`）：原结论 → 新证据 → 修改原因 → 新结论，并注明属于哪一类。反馈复核阶段按用户反馈修正的，类别写「反馈复核」。
用户说"不准"时先按 `shared/error_correction.md` 分诊，不要一律转向改出生时间。
