# 基础落地协议（内置）

本文件把本 skill 各模块已经写明的落地要求整理成一份内置协议，保证在没有安装外部 `oracle-grounding` skill 时，建议、时机和行动指引也能完整写出。装了 `oracle-grounding` 时，它作为增强层叠加在本协议之上；未取得其完整内容时，不声称已经按它执行。

## 1. 两阶段隔离

- 推导阶段只看盘面（`shared/permissions.md`），产出领域中立的结构判词。
- 翻译阶段才使用用户的领域与处境（行业、关系类型、目标）。只许翻译，不许新增、削弱或反转结构结论；翻译时发现结构判词与现实硬冲突，退回推导复查，不在翻译层悄悄圆。
- 置信度标签原样保留，翻译不升级置信度。

## 2. 关键结构写成三段链

信号 → 力学模式 → 该领域的现实表现清单。清单具体到用户能逐条核对（通常 3 条左右，按实际可写的数量写，不凑数）；写不出清单的结论要么重写，要么降级为"倾向"。

## 3. 建议的粒度

- 建议落到"结构改造"粒度：拆层、产品线、岗位与能力配置、可沉淀的工件、负面清单（不做什么）。
- 每条建议注明解的是哪个盘面张力（哪颗星、哪个格局、哪条冲突）。换一个人、换一个行业还成立的建议是空话，重写。
- 排除项（不需要追的方向）也要讲机制：为什么不用追。

## 4. 时机与格局写成条件

- 时间窗口在正负面判定之上加「宜 / 忌动作 + 条件分支」：做了 A 则此窗口为机会，没做则表现为忙乱。分支要能事后回测。
- 格局激活写成条件期权：若不做 X 则不兑现，做 X 则兑现；X 是用户能执行的动作。
- 中性的"动"类信号（行运触发、换运交接）不硬判吉凶，给事件类型加两个分支。

## 5. 行动卡

报告末尾一张行动卡：一句话结论、关键时机表、宜忌、要点。只压缩正文，零新增信息。时机表的精度不得细于正文实际读到的 Dasha 层级（没读 PD 不给月份；只读到 AD 写阶段窗口；只读到 MD 写背景趋势）。soul 模块可以不写行动卡，但实操段落要过第 3 条的质检。

## 6. 面向当事人的写法

- 先把盘立起来再展开；术语保留，出现时当场解释成能核对的具体表现。
- 每提出一个问题，同时给对应的做法。
- 给"现在就能核对"的判断时，除了"对得上 / 对不上"，还要给第三个出口：想不出来、没概念 = 还没取到样，附取样办法，并说明什么情况才算真的读偏。
