# 时间分辨率（正本）

本文件是「时间窗纪律」与「大运×小运叠加」的唯一正本。core、career、love、soul、timing、synastry 输出任何时间窗或时机结论都按本文件。

## 1. 窗口分辨率：MD / AD / PD 三层

- **MD（大运）只定背景**：大运级、Sade Sati 级信号只写成背景趋势，让用户听懂这是长期底色，不是具体时点。不要写"注：这不是事件窗口"之类元声明。
- **AD（小运）定阶段**：凡用"黄金期 / 窗口期 / 时机 / 将发生"等事件性措辞，至少落到 MD×AD 阶段窗口，并引用 Dasha 表的 AD 行。
- **PD（三级运）定月级候选**：点名月份、季度内先后，或任何窄于完整 AD 的窗口，必须读 calculator 原生 PD：
  `python calculator/scripts/dasha_query.py --file structured_data.md --month YYYY-MM`（或 `--date` / `--start --end`，`--context 1`）。
  脚本先做 MD/AD/PD 层级检查，PD 层未通过时拒绝给月级窗口。此时明确降级为 AD 阶段窗口；禁止用 AD 冒充月级精度，禁止按比例或 365.25 天近似推算。
- **出生时间误差对 Dasha 日期的影响**：Vimsottari 全表随出生时刻整体平移。平移天数 ≈ 有效误差（分钟）÷ 1440 × Moon 日速 ÷ 13°20′ × 起运主星年数 × 365.26（出生证 ±1 分钟约 ±2~5 天；±15 分钟可达 ±20~75 天）。`check_chart.py` 的能力范围按此给出：
  | 平移 | AD 阶段窗口 | PD 月级窗口 |
  |---|---|---|
  | ≤ 7 天 | 可用 | 可用 |
  | 7~30 天 | 可用 | 条件使用：PD 交界前后这段时间内不下月级结论 |
  | 30~120 天 | 条件使用：AD 交界前后这段时间内不定 | 不启用，只给 AD 阶段窗口 |
  | > 120 天 | 不启用，只作 MD 背景 | 不启用 |
  平移超过 1 年时，MD 交界前后这段时间也标「条件使用」。误差范围内 Moon 跨宿时，按两侧宿主星年数中较大者算平移（时间轴在宿界两侧连续，只有出生时正在走、已经过去的那段大运主星不同）。`dasha_query.py` 在月级窗口「不启用」时不给 PD，只输出该日期/区间的 MD/AD 行（退出码 2 = 月级未完成；定位今天或某事件所在的 MD/AD 照常用这份输出）；`--candidate` 只列 PD 候选表，不得写成月级结论。收窄误差靠更可靠的来源或校时，不靠验前事命中。
- 多个候选比较：先在 MD/AD 层锁定全部合格候选，再对全部仍需区分的候选统一下钻 PD；禁止只给最中意的候选读 PD，禁止通读后反向挑窗口。
- 默认不把 729 行 PD 整表读进上下文，用 `--overview` 折叠。

## 2. 非 Dasha 的时间来源（明确列出的例外）

- timing Mode C 年盘给的月份、Mode A 行运给的日期，来自年盘与真实星历，不受 PD 限制；但必须写明依据是年盘还是行运，年盘的简化部分保持简化标记（见 timing 模块「年盘能力限制」）。
- 未来行运日期只引 `structured_data.md`「未来过运换座时间表」或 `calculator/scripts/transit.py` 的计算结果；禁止凭记忆写换座日期。

## 3. 第二时间系统

Chara Dasha 共振只读 `structured_data.md`「Chara Dasha 时间线」；没有该表时禁止心算，也禁止写"双系统确认 / 共振"。表头提示「由 5.1 及更早的引擎生成」时（Scorpio / Aquarius 双主座规则已在 5.2 改正），先重排再用；没重排就只按单系统写。交叉验证细则在 timing Mode B。Chara AD、Yogini AD 是简化版，不单独支撑月级结论。

## 4. 回顾过去的 Dasha

同一 Dasha 的正面与负面表现按盘面实际情况列出，不因已知用户那段过得苦或顺而只写一面。P1 身份与尊贵度已明确定调时，主判定单向下定，另一面只用一句条件补充；不凑数，也不通篇对冲。

## 5. 三轴分别结算

领域轴、形态轴、时间轴分别结算后才合成事件候选（见 `core/resources/p1_p12.md`「三轴分离」）。领域被激活不等于形成或丧失；窗口分辨率只看实际读到的层级。

## 6. 大运 × 小运叠加

每个 Dasha 先按 `core/resources/house_framework.md`「判定逻辑」五档定档（危机 / 困难 / 混合 / 正面 / 平淡）。叠加时：

- 默认保留两层：「大运背景：X 档（依据）＋ 小运阶段：Y 档（依据）」。
- 有现行规则的组合按原规则执行（正面记为"正"，危机、困难记为"负"）：

| 大运 | 小运 | 读法 |
|---|---|---|
| 正 | 正 | 该领域顺利 |
| 正 | 负 | 好事多磨 |
| 负 | 正 | 困境中有转机 |
| 负 | 负 | 该领域面临危机：说清风险领域并给可操作的预防，不恐吓 |

- 任一层是「混合」或「平淡」：分层陈述两层各自的档位和依据，不得把混合、平淡擅自压成正或负，也不给统一的最终评级。
- 如需为全部组合新增统一评级，属于新的技法规则，须经用户确认后另行加入。
- 三级运 PD 只用于月级候选，不参与档位合成。

## 7. 时效

报告与 `structured_data.md` 的"→当前"标记是生成日快照。回答任何时机问题前，先用今天的日期重新定位 MD/AD/PD，并按 `shared/versioning.md` 跑 `shared/scripts/check_freshness.py`。
