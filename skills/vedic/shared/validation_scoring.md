# 验前事评分与时间精度（正本）

验前事（盘面初验）只回答一件事：这组探针和用户反馈对得上多少。它不是预测准确率，也不单独决定出生时间精度。

## 1. 登记

每轮验前事写入 `verification_record.json`（schema `vedic-verification/1.0`），绑定当前盘的 chart_id。每题记录：陈述、时间窗口、反馈、三个标志。

| 反馈 | 计分 |
|---|---|
| 准 `hit` | 1 |
| 部分准 `partial` | 0.5 |
| 不准 `miss` | 0 |
| 不知道 / 记不清 `unknown` | 不计分，单列待核，不删除 |
| 未答 `pending` | 反馈未完成 |

不计入独立验证的题（标志为 true）：
- `tautology` 恒真陈述：随机同龄人大概率也命中（宽窗口的高频人生节点、用"或"并列多个宽类别、想不出什么人生会让它不准）
- `known_fact` 已知事实核对：用户已经告诉过的事
- `used_in_rectification` 校时用过的证据：不能再冒充独立验证

复合推断拆成子项判；用户只确认一部分记"部分准"，不算全中。用户含糊（"可能吧"）不算准。

## 2. 定级（`shared/scripts/score_probes.py`）

有效探针匹配率 =（准 + 0.5 × 部分准）÷ 有效已答题数

| 情况 | 反馈等级 |
|---|---|
| 仍有未答题，或有效已答题少于 3 题 | 暂不定级 |
| 待核（不知道/记不清）题超过有效题的 1/3 | 暂不定级（先补答或换题；只按答得上的题定级会抬高匹配率） |
| ≥ 80% | 高 |
| ≥ 60%，< 80% | 中 |
| < 60% | 低 |

- 例：3.5/5 = 70% → 中；2.5/5 = 50% → 低。
- 有效已答题少于 5 题时标注「小样本」。
- 输出必须同时显示：总题数、不计入的题及原因、有效题数、已答题数（及占有效题的比例）、待核题、未答题、匹配率、等级。不能只给一个百分比。
- 记录有非法反馈或绑定的不是当前盘：等级记「无效」，不出等级。
- 这个等级就是下游所说的「信号解释置信度」（简化信号规则在这张盘上的适配度）。

## 3. 时间精度由谁决定

| 维度 | 由什么决定 | 不由什么决定 |
|---|---|---|
| 时间可信度、有效误差 | 时间来源（`shared/data_contract.md` §4）、D1 边界审计（上升在误差内换座且来源不是出生证/医院记录 → 再降一档）、rectifier 的校准达成级别；具体分档见 reader「时间可信度标注规则」 | 验前事命中率 |
| 信号解释置信度（反馈等级） | 本文件 §2 | 时间来源 |

- 验前事命中只能作为辅助证据。家人回忆的时间，命中再高也不能升级为分钟级。
- 时间来源可靠、反馈等级低：不归因于时间，进入 core 的反馈复核，检查规则在这张盘上的适配；也可能出生时刻正好在分盘换座点附近，可以建议核对，但不默认改时间。
- 时间来源不可靠、反馈等级低：建议 rectifier。

## 4. 校时之后

- 校时改了出生时间 → 新盘新 chart_id。旧验证记录保留，但绑定旧盘，不迁移成新盘的验证结果。
- 新盘需要验证时另建一轮记录；校时用过的证据在新记录里标 `used_in_rectification`。
- 每个 chart_id 只做一轮验前事（R1），不追加 R2/R3；校时或用户更正出生数据后的新盘是新的 chart_id，可以另做一轮。
- 新盘那一轮里，用户在旧盘上已经答过的事件事实再次出现时标 `known_fact`（已知事实核对，不计入独立验证）；新题优先选旧盘没问过、且新旧两盘结论不同的领域。

## 5. 偏差处理（替代旧的"反轴用户防御规则"）

用户对验前事或分析说"不准"时，按 `shared/error_correction.md` 分诊：数据问题、规则应用问题、解释形态问题、时间问题分别处理。不承诺"更深入的分析必然更准"，不追加新预测去弥补，不把用户反馈装作独立推断。
