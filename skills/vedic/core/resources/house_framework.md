## 诊断四维度

### 1. 管理者（宫头星/宫主）
```
查看宫主的：
  P1身份 → 它是什么角色？（读 structured_data「功能身份」表，口径见 p1_p12 P1）
  去向(落宫) → 它去了哪个宫位？把这个宫的能量带到了哪里？
  P7尊贵度 → 它健不健康？（读「复合尊贵度」列）
  P9 Shadbala → 它有没有力量执行？
```

### 2. 租客（宫内行星）
```
查看宫内星的：
  自带属性 → 吉星进驻=加持，凶星进驻=干扰
  合相情况 → 多颗星同宫=事务繁忙（合相=同宫；强弱按 p1_p12 P3「合相度数三档」）
```

### 3. 相位（谁在看这个宫位）
```
数据：只读 structured_data「Graha Drishti（吠陀行星相位·宫位照射）」表
  （星→宫整宫照射：全体 7th；Mars 另照 4th/8th，Jupiter 另照 5th/9th，Saturn 另照 3rd/10th；calc 已算好）
  ❌ 禁手推照射；❌ 禁用西占度数 orb 相位（合/六合/刑/三合/冲——不属 KN Rao 体系，
     原「主要相位关系」表已废弃删除）。

查看哪些行星照射此宫位（P10）：
  吉星照射 = 外部加持（保护/增益）
  凶星照射 = 外部压力（冲突/限制/放大）

  相位合成铁律（吉凶照射并存时，沿用"方向/执行分层"模式）：
    分层陈述——吉定结果保底、凶定过程摩擦
    ❌ 禁止择一而论（只报木星保护 或 只报土星限制）
    ❌ 禁止对冲抵消（"一吉一凶互相抵消"）
  多星照射 → 禁止笼统写"受多方面外部影响"，必须按上述铁律
    把每颗照射星归入"结果保底/过程摩擦"两层逐星陈述
```

### 4. 硬件带宽（SAV）

辅助维度，不定方向。

⚠️ SAV读取铁规（唯一定义，各模块引用处逐字同句）：引用任何宫位SAV值，必须从structured_data「宫位映射」表读取；禁止读「原始值（按星座）」表或自行计算sign→house映射；输出标注格式 N宫(Sign)SAV=X。

```
例："1宫(Pi)SAV=28" "7宫(Vi)SAV=16" → 用户可拿星座缩写去原始表交叉验证。

SAV是辅助确认指标。展示与提及统一为单点规则：仅极端值（>32 或 <20）时在数据表列出/在叙事中提及，
中间值(20-32)不展开。四档参考：
  SAV > 32 = 溢出（资源充裕）
  SAV 26-32 = 平稳（正常运作）
  SAV 20-25 = 紧张（需要额外努力）
  SAV < 20 = 匮乏（结构性不足）

降权三条（与尊贵度/身份不等权）：
  1. SAV 不进大运正/负面计数（见下方「大运正负面判断规则」），不加减档位；
  2. SAV 不定方向、不定路径、不单独成立格局或"准格局"，只作强度佐证；
  3. 叙事起点必须是 P1(角色) 或 P7(尊贵度)；SAV 只能出现在段落第二句以后，
     禁止以"X宫SAV=Y"开头一段分析。

特殊：凶宫(6/8/12) SAV低 = 反而是防火墙（贼进空屋）
      凶宫(6/8/12) SAV高 = 反转效果（破坏资源充足）
  适用边界：本条仅指该宫灾祸类事件的频率/强度层（6=疾病/官非、8=突变/危机、12=损耗），
    不适用于该宫正面义项（6=竞争/服务力、8=遗产/研究、12=海外/灵性）与掌宫行星的资源评估——
    正面义项与掌宫资源仍按上方四档正读（低=匮乏、高=充裕），见 p1_p12 P4 适用边界。
  ⚠️ 防火墙/反转属解读逻辑层，不受"仅极端值展示"门槛约束——凶宫 SAV 落 20-25 也照常参与
     防火墙/资源解读，只是不单列进 SAV 展示行。
```

## 宫位评级

```
创始人模式：宫主强+宫内有吉星+吉星照射 → 自主掌控
创始人模式（带阻力）：宫主强+凶星照射 → 仍自主掌控，但过程带阻力（按相位合成铁律分层陈述）

吉祥物模式：宫主弱+有吉星照射 → 有贵人帮但自己弱
飘萍模式：宫主弱+无吉星+凶星照射 → 该领域缺乏根基
（SAV极端值可作为模式判定的辅助确认，但不作为主要判据）
```

## 多阶段事件推导

大事件不是单一时间点，而是分阶段展开，每个阶段由不同宫主的Dasha触发：

| 事件 | 阶段1 (启动) | 阶段2 (落地) | 阶段3 (收益) |
|------|-------------|-------------|-------------|
| 结婚 | L7 (关系确立) | UL 主 / Jupiter 过 UL / Sun-L7 同步 (法律确认) | L11 (社会公开) |
| 换工作 | L10 (机会/决定) | L6 (入职/竞争) | L11 (收入到位) |
| 买房 | L4 (动念/看房) | L2 (出钱/签约) | L4+D4 (入住) |
| 出国 | L9/L12 (决定) | L12 (离开) | L4 (安家) |

### 婚姻时间推导（三阶段模型）

现代婚姻是过程不是瞬间，Dasha 映射三个阶段：

```
阶段1 — 关系确立/承诺：L7 宫主的 MD/AD
阶段2 — 法律确认(领证)：
  → 主指标：UL (Upapada Lagna) 主的 MD/AD，或 Jupiter 行运到 UL
  → 辅助指标：Sun（官方/政府文件指示星）与 L7 / UL 的 Dasha 同步
  → 弃用：v2 曾用 L9 作为法律确认指标，但 L9 主管 dharma/远方/导师/父亲，
         "领证"挂到 L9 的逻辑链不强（L9 与"政府/契约"无直接关联），
         所以改用 UL（专属婚姻实现点）+ Sun（官方文件）。
阶段3 — 社会公开(婚礼/喜宴)：11 宫相关行星的 MD/AD（社交圈见证）

⚠️ Venus 不是婚姻首选触发器，除非 Venus 恰好是 L7 或 UL 主
⚠️ 三个阶段可能在同一个 Antardasha 内，也可能跨 2-3 个
⚠️ 输出格式："关系确立窗口在 [L7 期间]，正式落地在 [UL 主 / Jupiter 过 UL 期间]"
   不要说 "YYYY 年结婚" 这种单点预测
⚠️ 三轴护栏（领域 ≠ 形态 ≠ 时间，详见 p1_p12「三轴分离」）：
   L7 / UL 主 / Venus 当值只回答"关系领域被点名"（领域轴）；
   能否形成、正式化、维持还是重组/中断，须另看形态轴（D9 承载、关系主星状态、
   2/8/12 宫阈值、保护与受损反证）；窗口精度按下方「时间窗纪律」（MD 背景 / AD 阶段 / PD 月级）。
   ❌ 禁止把单一宫主当值直接写成"结婚"；❌ 禁止用 Ketu / 8 宫单点直接写成"分离"。

⚠️ UL 读 structured_data「特殊点位」表（calculator 已算）；表里没有 UL 的旧盘 → 回 calculator 重排，不手算。下面的公式只用于看懂 UL 的含义：
  UL / Upapada Lagna = 第 12 宫的 Arudha Pada（A12 / Vyaya Pada）
  ⚠️ 注意：UL 是从第 12 宫主推出来的，不是从第 7 宫主。把 L7 公式套到 UL 上是常见错误，
     那样算出来的是 A7 / Darapada（配偶的 Arudha），不是 UL。

  标准计算步骤：
  1. 找出第 12 宫（从 Lagna 起的第 12 宫）
  2. 找出第 12 宫主所在星座
  3. 从第 12 宫数到第 12 宫主所在星座，得到距离 N（包含起点和终点）
  4. 从第 12 宫主所在星座再向前数 N 个星座，得到的星座 = 初步 UL
  5. Arudha 例外规则：若初步 UL 落在第 12 宫本身或第 12 宫的对宫（即从 Lagna 看的
     第 12 宫 / 第 6 宫），则从该初步点再数第 10 宫作为最终 UL
  6. UL 主 = UL 所在星座的统治行星
  7. 若与 JHora / Parashara's Light 输出不一致，以软件结果为准（不同流派对 Arudha
     例外的处理略有差异，必须记录所用流派）

  ⚠️ 区分：
    - UL = A12 = 婚姻 / 法律落地点 (Upapada)
    - A7 = Darapada = 配偶在世界中的呈现 (与 UL 不同，常被混淆)
  
  UL 是 Jaimini 体系专属的婚姻实现点，对法律性的婚姻成立最敏感
```

### 大运正负面判断规则

大运星的正负面不是"感觉"，是有明确判定条件的：

⚠️ 节点例外：大运/小运星为 Rahu/Ketu 时，本节正负面条件不可计算（节点无掌宫身份/自身尊贵度/Shadbala）——改用 p1_p12「P7.4 节点(Rahu/Ketu)强弱判定唯一口径」里的「Dasha速查表节点专用正负面条件子表」；速查表节点行"大运星P1"列填"—（节点不掌宫）"、"尊贵度"列填定位星状态。

⚠️ **P1身份读 structured_data「功能身份」表"主身份"列**（calc 按 Moolatrikona 宫定主，禁自判；Lagna 主恒为 Core-Driver，见 p1_p12 P1）；一星身兼吉凶宫主（"身兼吉凶"=是）→ 正/负面条件1 **按主身份计一次、不双计**（兼管的另一宫作叙述注明、不另计对侧）。

#### 正面条件（满足≥2条→判定为正面）
```
1. P1身份=吉角色（Core-Driver / Yogakaraka / Faithful）
2. P7尊贵度≥友方（至友/友方/入庙/Moolatrikona/入旺；读「复合尊贵度」列）
3. P9 Shadbala≥120%
4. 落在吉路（1/4/5/7/9/10宫）
5. Vargottama或Dig Bala加成
```

#### 负面条件（满足任一即标注风险）
```
1. P1身份=凶角色（Trika-Lord 管 8/12 或 Growth-Hacker 管 6）
2. P2受损（燃烧/落陷/败相）
   ——"落陷"专指 debilitated；死敌(great_enemy)/敌方是环境兼容档，不计本条（见 p1_p12 P7）
   ——落陷若经 NBRY【完全补救】（视同正常行星，见 p1_p12 P7 NBRY）则**不计落陷**；
     燃烧/败相仍计。部分/强力补救仍计落陷，叙述注明缓冲
3. 落在凶路（6/8/12宫）且无VRY补救（VRY 判定见 p1_p12 P5 唯一定义）
4. P9 Shadbala<100%
5. 与凶星紧密合相（同宫且<5°）
```

> ⚠️ **SAV 不计入上述正/负面主计数**（旧版正面"管的宫位SAV≥28"、负面"管的宫位SAV<25"两条已移除）——非极端阈值 28/25 会让辅助指标与 P1身份/P7尊贵度等权计票。SAV 仅在达**极端值(>32 或 <20)** 时，作为"方向已由上述条件判定后"的**叙事备注**（不进档位计数、不加减档位），见 §4 硬件带宽。

#### 判定逻辑（按顺序判定，首个命中即停——互斥、全覆盖）
```
1. 危机期：正面=0 且 负面≥2 → 需谨慎/有风险（最严条件先判）
2. 困难期：正面<2 且 负面≥1 → 该领域面临挑战
3. 混合期：正面≥2 且 负面≥1 → 发展中伴随压力
4. 正面期：正面≥2 且 负面=0 → 该领域顺利/上升
5. 平淡期：以上都不中（即 正面<2 且 负面=0）→ 无显著信号，该领域平稳过渡（兜底）

⚠️ 必须从1往5顺序判，首个命中即定档；禁止乱序读表。
```
