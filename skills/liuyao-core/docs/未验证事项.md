# 未验证事项（v6.1）

## 线上能力，没有条件测

1. **真实 Jev 接口**：本次没有密钥，只测了 mock 与各类伪造的异常返回。真实返回的字段结构（尤其是否返回全部选项的概率）与 `validate_response` 的假设是否一致，需要配好 `TYPESAFE_API_KEY` 后先跑 `python scripts/jev_eval.py --lang both`。若真实接口只返回前几名概率，校验里"概率总和"一项会放行，但"缺选项"不会误判，需看第一次真实结果再定。
2. **新增的问法类型题**（`wenfa_type`）与 3 条新金标准例没有在真实 Jev 上跑过，歧义阈值沿用旧值。
3. **真实排盘截图**：`--verify` 用的是模型读出后的字段 JSON，测试只覆盖了这一步之后。模型从图片读字段的准确率没有测。
4. **安装后的行为**：使用情境测试是让模型直接读工作目录里的文件，没有走 skill 安装后的触发与加载路径。

## 规则层面的取舍，请你确认

5. **R12 合墓能否解墓、R26 静爻值日能否通关**：资料本身两说并存，本次只定了"默认怎么做、怎么标源"，没有证据判哪一说对。需要复盘记录积累后再定。
6. **铜钱字背约定**：只确认了坊间有两种相反算法，并让脚本必须指定约定；没有核对哪本古籍用哪一种。本包默认沿用原 `14` 表（字记 3、背记 2）。
7. **健康卦的置信度上限**：情境 S08 里，双镜冲突但已仲裁，按规则给了"高"，结论是"难好"。规则上没错，但对代测亲人病情这类问题，是否应设"最高为中"之类的上限，是政策选择，本次没有替你定。
8. **R06 静爻受生**：默认改为按曲炜四层次与《增删》（动爻、日月可生静爻），"不动之爻不得生"降为邵/林派说法。这是依据原 v5.2 断语标源第②条推出的，影响面较大，第一批复盘时值得重点看。

## 精度与范围

9. **节气时刻**：用低精度天文算法，实测最大误差 14 分钟；未确认带宽设为 60 分钟。没有做真太阳时校正；海外时区只按钟表时间与 UTC 偏移换算。只支持 1900–2100 年。
10. **子时换日**：23～24 点未指定约定时一律标未确认，不替用户选；晚子时的时干给两个候选。没有在资料里找到本包应默认哪种约定。
11. **甲类触发清单**里标"半"的项（暗动 / 日破、真空 / 假空、入墓 / 入库等）脚本只给前提事实，结论仍由模型判，这部分的一致性只有使用情境抽测，没有系统测试。

## v6.1 新增

14. **R27 土爻逢土月冲**：默认以月破论，依据只是"专门规定优先"和此前断卦里的一贯做法（戌月辰爻按月破读）；没有复盘数据说明"破"与"旺"哪个读法更准。土月占全年三分之一，这条碰到的机会多，复盘时值得单独统计。
15. **R29 静爻逢动爻为墓**：`06` 三、四两说相抵，原书未随包分发，无法回查哪一句是转述走样。现在只列事实、不作唯一依据。
16. **R28 化墓范围**：默认从主流（只论本五行之墓）。墓书"即使非自墓"的卦例本包没有样本。
17. **时区**：只解决了"月建会不会因时区而不同"。日辰一律随起卦地的钟表日期，没有处理"人在海外是否该按北京日期论日辰"这一说法之争，也没有真太阳时。1986–1991 年中国实行过夏令时，脚本不处理，换算这段时间的夏季时刻要自己减一小时。
18. **使用情境没有重跑**（见测试报告）。新增的"时区未指明"追问、触发清单新增的几类条目，模型实际会不会照做，还没有行为层面的验证。
19. **Jev 的语言**：有第三方资料称该模型以英语为主，`jev_judge.py` 默认发中文题干。配好密钥后先跑 `python scripts/jev_eval.py --lang both` 比一比再定默认语言。
